1. Pendahuluan
1.1 Tujuan Dokumen
Dokumen Software Requirements Specification (SRS) ini menjelaskan kebutuhan sistem Road2Work.id versi terbaru. Dokumen ini digunakan sebagai acuan bersama untuk tim frontend, backend, AI engineer, data scientist, QA, dokumentasi, dan stakeholder capstone agar implementasi produk tetap konsisten dengan overview dan API Contract v2.3.
1.2 Scope Dokumen
SRS ini mencakup kebutuhan produk Road2Work.id sebagai AI Career Readiness Platform dengan fokus MVP pada professional profile, role fit, adaptive voice interview, career readiness dashboard, quota interview, admin panel, serta adaptive interview antar session.

2.1 Product Perspective
Road2Work.id adalah platform AI Career Readiness yang membantu mahasiswa, fresh graduate, career switcher pemula, dan pencari kerja mempersiapkan diri menuju dunia kerja secara lebih terarah. Fokus utamanya adalah membantu user memahami profil profesional, role fit, kesiapan interview, dan langkah perbaikan berikutnya.

3.1 Career Switcher Pemula dalam Road2Work.id
Dalam case Road2Work.id, career switcher pemula adalah user yang ingin pindah ke role baru, misalnya dari organisasi, freelance, marketing, event, customer service, atau project kampus non-IT menuju role seperti Data Analyst, Product Analyst, AI Engineer, Backend Developer, atau ML Engineer. Sistem harus membantu user menemukan transferable skills dan menjelaskan pengalaman lama agar relevan dengan target role.
Contoh: user yang pernah mengelola event dapat diarahkan untuk menjelaskan pengalaman menganalisis data peserta, feedback audiens, performa campaign, koordinasi tim, dan pengambilan keputusan berbasis insight. Interview untuk career switcher perlu menggali alasan transisi, skill yang sudah dipelajari, gap yang masih ada, dan bukti belajar mandiri.

Pertanyaan interview ulang dapat menargetkan competency yang sama, tetapi wording dan konteks harus disesuaikan dengan weakness sebelumnya.

6.4 HRD Interview State
State
Fungsi
Behavior Sistem
Idle
HRD siap memulai interview.
Menunggu user menekan Start Interview atau sistem menyiapkan pertanyaan awal.
Asking
HRD sedang mengajukan pertanyaan.
HRD WebM asking aktif, question bubble tampil, mic belum merekam.
Listening
HRD sedang mendengarkan jawaban user.
Mic otomatis aktif, timer 90 detik berjalan, recording tetap berlangsung walaupun user diam.
Thinking
AI sedang memproses jawaban.
Recording berhenti, audio dikirim ke backend, STT dan answer evaluation berjalan.
Clarifying
HRD meminta klarifikasi atau detail tambahan.
Sistem menampilkan pertanyaan follow-up berdasarkan weakness detection.
Completed
Sesi interview selesai.
Result dibuat, dashboard diperbarui, user dapat melihat hasil atau latihan lagi.
6.5 State Transition

Thinking â†’ Clarifying â†’ Listening â†’ Thinking
Thinking â†’ Asking
Thinking â†’ Completed
Catatan:
- Recording/timer bukan state terpisah, tetapi behavior dalam state Listening.
- STT/evaluation bukan state terpisah, tetapi behavior dalam state Thinking.
- Error handling dapat menggunakan state tambahan error di level teknis, tetapi bukan core HRD product state.

10. AI/ML Requirements
10.1 AI Principles
GenAI tidak boleh menjadi satu-satunya sumber scoring.
Scoring harus menggunakan pendekatan hybrid: rubric, role-skill matrix, Evidence Ladder, weakness taxonomy, TensorFlow supporting model, dan GenAI wording.
AI tidak boleh mengarang pengalaman, angka, tools, impact, atau achievement yang tidak disebut user.
AI harus menghasilkan pertanyaan natural tetapi tetap dikontrol oleh competency map dan role-skill matrix.
AI harus mempertimbangkan interview history saat user melakukan interview ulang.

14. Acceptance Criteria dan Definition of Done
14.1 MVP Acceptance Criteria
User bisa sign up dan login.
User bisa memilih Upload CV atau Isi Profil Manual.
Pada CV path, sistem bisa extract CV, membuat profile draft, review/edit profile, generate Role Fit Ranking, dan confirm selected role.
Pada manual path, user bisa memilih Domain, Role Family, Target Role, mengisi profil singkat, review/edit profile, dan langsung memakai selected role.
Role Fit Ranking tidak muncul pada manual path.
Role Fit Score dapat muncul di dashboard pada semua path.
User bisa memulai adaptive voice interview jika quota tersedia.
Pertanyaan pertama adalah perkenalan diri.
Mic otomatis aktif setelah HRD bertanya dan timer 90 detik berjalan.
Mic tetap aktif walaupun user diam.
User dapat menekan Mic Off sebelum 90 detik untuk menyelesaikan jawaban.
Sistem bisa melakukan STT internal dan mengevaluasi jawaban.
Sistem bisa menghasilkan clarifying question jika jawaban kurang jelas atau evidence lemah.
Sistem bisa menghitung final interview readiness score.
Dashboard menampilkan Career Readiness Score, score breakdown, strengths, gaps, next best actions, dan latest interview feedback.
Jika user interview lagi, sistem membaca evaluasi sebelumnya dan menghindari pertanyaan yang sama persis.
Admin dapat melihat analytics dan mengelola data role dasar.
README dan dokumentasi setup tersedia.

15. Risiko dan Mitigasi
Risiko
Dampak
Mitigasi
Scope creep
Fitur terlalu banyak dan MVP tidak selesai.
Kunci P0 terlebih dahulu; fitur job portal/payment/advanced analytics masuk future plan.
Pertanyaan AI terlalu random
Interview terasa tidak relevan dengan role.
Gunakan role-skill matrix, competency map, question seed, dan guardrail.
Feedback terlalu generik
Dashboard terasa seperti chatbot biasa.
Gunakan rubric, weakness detection, Evidence Ladder, dan data jawaban user.
STT kurang akurat
Jawaban user salah dipahami.
Gunakan clarification mode, STT confidence, dan fallback demo.
Latency AI tinggi
Interview terasa lambat.
Tampilkan Thinking state, batasi jumlah pertanyaan, dan gunakan caching untuk role/profile context.
Question repetition
Interview ulang terasa sama.
Simpan askedQuestionHistory dan gunakan avoidRepeatedQuestions.
Model TensorFlow kurang akurat
Score kurang reliable.
Jadikan TensorFlow supporting score, bukan sumber tunggal scoring.
Deployment bermasalah
Demo gagal.
Siapkan local demo, dummy data, video backup, dan fallback response.
